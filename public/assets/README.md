# 图片资产规格

这里的图片全部是**现成的静态文件**，运行时不经过任何模型生成，也不向任何第三方发请求。
直接把成品图按下面的文件名放进来即可，代码无需改动。

格式统一用 `.jpg`（渐进式、质量 80–85 即可）。风格统一为 **2D 插画**。

---

## 美术方向

参照《旷野之息》的美术语言。UI 框架已经按这套语言做好了（暖石板面板、柔金细描边、羊皮纸地图、中西文双衬线），**成品图的质感直接决定最终观感的上限**——框架能衬托好图，但补不上图本身的差距。

### 要的

| | 说明 |
|---|---|
| **色调** | 大地色系：暖褐、米黄、苔绿、陶土。整体低饱和，只在关键处给一点高饱和点缀 |
| **光** | 单一主光源方向明确，柔和的暖色边缘光。阴影是有颜色的（偏蓝紫），不是灰黑 |
| **笔触** | 看得见的水彩／色粉质感，允许边缘不完美。完全均匀的数字色块是廉价感的主要来源 |
| **描边** | 细。塞尔达几乎不用粗黑描边，靠明暗交界区分形体 |
| **留白** | 大胆留空。背景不必填满细节 |

### 不要的

- ❌ **霓虹发光、赛博朋克配色**（青紫高饱和）—— 这是项目原本的方向，已经全部移除了，别再带回来
- ❌ **3D 渲染感**：金属反射、次表面散射、景深虚化
- ❌ **粗黑描边 + 纯平色**（那是另一种风格，和这套 UI 冲突）
- ❌ **高对比、强锐化**——塞尔达的画面其实很柔

### 参考锚点

出图时可以拿这几样当基准：BotW 的**希卡之石地图**（羊皮纸底、极简标注）、**任务记录界面**（深石板半透明面板 + 细金线）、**人物立绘的光影处理**（柔和、边缘光、有色阴影）。

## 一、角色立绘 `avatars/`

玩家的相貌由系统随机抽取，抽中哪张就是哪张。

共 12 个种族，每个 4 张变体 = **48 张**。文件名前缀见下表，序号 `-01` 到 `-04`。

**每个种族必须男女各半**：`-01` `-03` 为男性，`-02` `-04` 为女性。

这一条容易被忽略——出图时如果不在提示词里显式写性别，模型会默认画女性，48 张会清一色是女的，男性玩家抽到自己的相貌时没有代表性。生成脚本里性别词已经放在提示词最前面（权重最高），自己画或换工具时也要保持这个约束。

| 前缀 | 种族 | 视觉要点 |
|---|---|---|
| `slime` | 利姆鲁·史莱姆 | 半透明蓝、无固定形态感、小皇冠 |
| `kijin` | 鬼人族·侍大将 | 赤色鬼角、和风战装 |
| `daemon` | 原初之黑·恶魔 | 暗色角与尾、正装 |
| `dragonnewt` | 龙人族·龙战士 | 小龙角、鳞片、尾 |
| `angel` | 天翼族·歼灭天使 | 白翼、光环、白金配色 |
| `elf` | 森精灵·守林人 | 长耳、藤蔓与叶饰、林绿 |
| `dwarf` | 矮人族·锻炉子嗣 | 敦实身形、编须或编发、皮革与铜件 |
| `beastkin` | 兽人族·野性同盟 | 兽耳与尾、野性纹样 |
| `fairy` | 妖精族·微光使 | 小体型、透明薄翅、身周微光 |
| `undead` | 不死者·长夜行者 | 苍白肤色、缝合或裂痕、暗紫 |
| `merfolk` | 人鱼族·潮汐歌者 | 鳞纹、鳍状耳、水色渐变 |
| `golem` | 傀儡族·不眠石心 | 石质或陶土肌理、接缝、胸口核心 |

**48 张是不小的量**。想减负可以把 [`lib/avatar.ts`](../../lib/avatar.ts) 的 `VARIANTS_PER_RACE` 改成 2，先出 24 张跑起来，之后再补 `-03`、`-04`。序号必须从 01 连续，中间不能缺号。

- **尺寸**：768 × 1024（3:4 竖版）
- **构图**：半身或胸像，人物居中偏上，**下方三分之一会被渐变遮罩压暗并叠加文字**，别把脸放太低
- **背景**：简洁，不要复杂场景——这些图会被裁切进小卡片和圆角头像框
- **数量可调**：想每个种族放 6 张就改 [`lib/avatar.ts`](../../lib/avatar.ts) 里的 `VARIANTS_PER_RACE`，文件按 `-05`、`-06` 顺延

序号必须是**两位数、从 01 连续**，中间不能缺号（`slime-01`、`slime-03` 而没有 `slime-02` 会抽到 404）。

## 二、艾琳娜表情立绘 `elena/`

她的立绘是**人工定稿的美术图，不由脚本生成**。`npm run assets` 会跳过这个目录——脚本按文字重画出来的是另一个人，跑一次就会把定稿覆盖掉。

角色设定在 [`lib/elena.ts`](../../lib/elena.ts)：`ELENA_PERSONA.visualPrompt` 是依据定稿反写的形象基准，`EXPRESSION_PROMPTS` 是每个表情与基准的差异。

**补新表情时**：用 `visualPrompt` + 对应的那一句差异，**其余一个字都不要改**。服装、发型、罗盘徽章、袖口蜂窝纹、背景的拱窗与书架，任何一处漂移，看起来就不是同一个人了。

**表情用整张立绘切换**，不在单张图上叠模拟眨眼与口型。各张姿势不同，五官位置对不齐，硬编码坐标必然错位；而且真实绘制的表情，表现力远好过让一张图假装在眨眼。

| 文件名 | 表情 | 用在哪 |
|---|---|---|
| `elena/neutral.jpg` | 平静 | 默认态、搜索无结果 |
| `elena/smile.jpg` | 微笑 | 加入小队、好友请求已发送 |
| `elena/playful.jpg` | 俏皮、带点得意 | 打开契约终端的招呼、发现新冒险者 |
| `elena/warm.jpg` | 温柔、欣慰 | 送冒险者出发 |
| `elena/stern.jpg` | 严肃、审视 | 尚未使用，留给警告类台词 |
| `elena/joy.jpg` | 明显的高兴 | **待补** — 任务验收、获得执照、创建小队 |
| `elena/sad.jpg` | 失落 | **待补** — 退出小队 |
| `elena/angry.jpg` | 不悦 | **待补** |

- **尺寸**：1000 × 1500（2:3）
- **构图**：半身，人物占画面高度 60–80%，头顶留白
- **一致性**：同一发型、同一套制服、同一背景。只变表情和手部姿势——这是"同一个人"的关键
- 待补的三张缺失时会自动退回：`joy` → `smile`，`sad` → `neutral`，`angry` → `stern`。补齐后把它加进 `lib/elena.ts` 的 `AVAILABLE_EXPRESSIONS` 即可生效

要增删表情，改 `lib/elena.ts` 的 `ElenaExpression` 与 `ELENA_LINES` 里每条台词的 `expression` 字段。

## 四、占位图

正式图还没做好时，可以先用脚本生成一套能跑的占位图：

```bash
npm run assets:images
```

它会跳过已存在的文件，所以**你把成品图放进来之后再跑也不会被覆盖**。要强制重做加 `-- --force`。

缺图不会导致崩溃：立绘缺失时觉醒流程会显示种族名占位块，背景图缺失时自动隐藏。
