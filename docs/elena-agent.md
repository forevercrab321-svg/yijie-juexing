# 艾琳娜 · 对话模式

她从「按钮触发固定台词」变成了**会即兴说话、并且能动手接委托的 NPC**。
这份文档只讲两件你之后要动的事，加上一份架构说明。

---

## 一、给她定性格 —— 只改一个地方

打开 [`lib/elena.ts`](../lib/elena.ts)，找到 **`ELENA_PERSONALITY`**。

那是一个普通对象，现在填的是一份克制的默认值，只保证她不出戏、没有鲜明个性。
改完**刷新页面即可生效**，不需要重跑任何脚本、不需要重启 dev server。

```ts
export const ELENA_PERSONALITY: ElenaPersonality = {
  selfImage:    '…她怎么看自己，一到两句',
  speechHabits: ['句子长短、爱用什么词、怎么开头收尾'],
  temperament:  ['什么时候会高兴、什么时候会收敛'],
  catchphrases: ['标志性说法，最多三条'],
  cares:        ['她在意的东西，会影响她主动提起什么'],
  dislikes:     ['会让她冷下来的事'],
  hardRules:    ['绝对不能破的，这部分会被单独强调'],
  freeform:     '上面装不下的，整段原样进提示词',
};
```

### 写的时候注意四件事

1. **写具体行为，别写形容词。**
   「会先问你吃饭了没」比「温柔」有用得多。模型对形容词的解读非常发散，
   对具体行为的复现则相当稳定。

2. **一条一句话。** 长段落的遵守率明显低于短句。

3. **`hardRules` 少放。** 它会被放在提示词结尾单独强调——模型对开头和结尾的
   遵守率最高。放三条以内有效，放十条等于没放。

4. **`catchphrases` 最多三条，并且别指望她每句都用。**
   提示词里已经写了「偶尔出现才像口头禅」，塞太多她会变成复读机。

### 改性格**不会**影响的东西

- **固定台词的语音**（`ELENA_LINES` 那十条 mp3）。那是预生成的音频文件，
  改性格不会重新生成。想让固定台词也换语气，得改台词文本再跑 `npm run assets:voices`。
- **她的形象**（`visualPrompt`）。性格和长相是两个字段。
- **她的职责边界**（`ELENA_SCOPE`）。那是产品责任面，不属于性格，见下。

### 性格 vs 边界

两者刻意分开放：

| | 在哪 | 改动性质 |
|---|---|---|
| **性格** `ELENA_PERSONALITY` | 她**怎么**说话 | 随时可改，纯风格 |
| **边界** `ELENA_SCOPE` | 她**能管什么** | 改这里等于改产品的责任面，要慎重 |

当前边界：**她只管委托**——发布、讲解、确认还在不在、确认接取。
委托之外的事她会说明自己管不着，然后把话题带回来。

要扩她的能力，三处必须同步改，否则她会说自己能做某件事却调不出工具：

1. `lib/elena.ts` 的 `ELENA_SCOPE.handles`
2. `lib/agent/tool-schema.ts` 加工具定义
3. `lib/agent/tools.ts` 加对应的执行分支

## 二、接本地语音输入

[`lib/agent/stt.ts`](../lib/agent/stt.ts) 是留给你的插槽，**现在是空的**。

项目不接任何云端 ASR——音频不离开这台设备，PRIVACY.md 的「数据不出本机」因此依然成立。
识别由你放进来的开源引擎在浏览器本地完成（whisper.cpp / sherpa-onnx / Moonshine 之类，
编译成 WASM 跑在 worker 里）。

录音、按住说话、打断、把结果送给她——**这些都已经做好了**。
你只需要回答一个问题：这段音频说了什么。

```ts
import { registerSttEngine } from './lib/agent/stt';

registerSttEngine({
  name: 'whisper-tiny-wasm',
  async load() {
    // 把模型加载进 worker。第一次点麦克风前会被调用一次。
  },
  async transcribe(audio, signal) {
    // audio 是 MediaRecorder 产出的 Blob，通常 audio/webm。
    // 需要别的格式就在这里转，不要反过来要求应用改录音方式。
    return '识别出的文字';
  },
});
```

在 `index.tsx` 里注册一次即可。注册之前麦克风按钮是禁用状态并标明原因，
不会假装能用，也不会偷偷退回任何云端识别。

> 加了本地语音后仍会触发浏览器的麦克风权限弹窗。由于音频不出设备，
> ConsentGate 和 PRIVACY.md 不需要新增数据类别；但**建议**在同意页加一句说明，
> 让用户知道麦克风用来做什么。

## 三、架构

```
              ┌──────────── 浏览器 ────────────┐
麦克风 ──▶ MediaRecorder ──▶ lib/agent/stt.ts（本地引擎，你来接）
                                    │ 文字
                                    ▼
                          hooks/useElenaAgent.ts
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │ POST /api/chat (SSE)      │ 工具在本地执行             │
        ▼                           ▼                           │
  server/chat.ts              lib/agent/tools.ts                │
        │  ← 唯一持有 API key         （读 state / 动地图 / 签约）│
        │  ← system prompt 在这里组装       │                    │
        ▼                                  └────────────────────┘
  MiniMax Chat Completions                          │ 结果塞回 messages
   （stream + tools）                                 └──▶ 再跑一轮
        │ 流式文本
        ▼
  按句切（conversation.ts: takeSentences）
        │ 一句一句
        ▼
  POST /api/tts ──▶ useElenaVoice 排队播放 ──▶ 🔊
```

### 几个关键决定

**为什么工具在客户端执行。**
它们要读 React state、动地图、改本机档案——这些都不在服务端。
服务端只把模型吐出的 `tool_calls` 原样转发，自己一个都不执行。
前端执行完把结果塞回 `messages` 再请求一次，形成闭环（最多 3 轮，防死循环）。

**为什么按句切而不是等整段。**
她开口的时间点取决于**第一句多长**，而不是整段生成完要多久。
第一句通常十来个字，合成很快——玩家的感受是她**立刻**开口了。
这是「活着」和「机器人」的分界线。

**为什么固定台词和对话共用一条音轨。**
`useElenaVoice` 是全应用唯一的音轨。不共用的话，
点击接取触发的固定台词会和她正在说的话同时响，听起来像两个人在抢麦。
所以她自己通过 `accept_quest` 签约时，`acceptQuest(q, { silent: true })`
会跳过固定台词，让她用自己的话讲。

**为什么 system prompt 在服务端组装。**
和 `/api/tts` 同一个道理：客户端只能传对话历史和一份收窄过的上下文，
`role: 'system'` 会被直接拒绝。否则任何人都能把这个端点当通用聊天网关用。

**表情怎么切。**
她每次回复的第一个字符是 `[expr:xxx]` 标记，前端解析后切立绘、剥掉标记再显示和朗读。
标记在流的最前面，所以**表情比声音先到**——她先有反应，然后才开口，这一点很关键。
忘了加标记、加错了、加在中间，三种都兜住，兜不住就按 `neutral`，绝不会因此吞掉整句话。

## 四、环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `MINIMAX_CHAT_MODEL` | 否 | 默认 `MiniMax-M2.7`。**必须与账号实际开通的模型对上**，不对会收到上游 400。 |
| `MINIMAX_CHAT_PATH` | 否 | 默认 `/v1/text/chatcompletion_v2`。收到 `AI_CHAT_PATH_INVALID` 就换成 `/v1/chat/completions`。 |
| `MINIMAX_TTS_MODEL` | 否 | 默认 `speech-2.8-hd`。2.6 系列已被列为 Legacy。 |

> ⚠️ **上面前两项没有经过线上验证**——写这套代码时 MiniMax 文档站被网络策略挡住，
> 模型名与接口路径是依据公开资料推断的。第一次跑起来如果报
> `AI_CHAT_PATH_INVALID` 或上游 400，不用改代码，改这两个环境变量即可。

## 五、成本与限流

- `/api/chat` 限流 20 次 / 60 秒 / IP，比 `/api/tts` 的 30 次更紧——对话轮次本来就该稀疏。
- 单次回复上限 512 token，人设要求三句以内，这个上限防的是失控长输出。
- 历史只保留最近 24 条消息，不做摘要压缩（柜台对话聊的是「哪个委托、在哪、能不能接」，
  二十句前说过什么基本不影响当下判断，花一次模型调用去压缩不划算）。
- **语音是大头。** 她说的每一句都要合成一次。界面右上角有语音开关，
  关掉后她只打字不出声。
