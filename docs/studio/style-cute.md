## 1. 风格定义

**一句话：晴天里的纽约玩具地图——明亮的草绿陆地、奶油色道路、圆润的粉彩小楼和棒棒糖树，Q 版的你站在画面下方，五种形状的委托徽章在街角轻轻浮动；界面是白色的大圆角软糖面板，按下去会扁、弹出来会蹦。**

关键词：明亮 · 干净 · 圆润 · 软 · 有弹性 · 一眼看懂。
反关键词：写实 · 暗沉 · 锐利 · 霓虹 · 赛博朋克青紫 · 粗黑描边 · 大面积深色界面 · 金色细描边 · 衬线古典字。

### 1.1 借鉴什么（这一类「步行 + 地图」手游的通用视觉语言）

| 借鉴 | 我们的做法 |
|---|---|
| 明亮的简化地图：浅绿陆地、浅色道路、亮蓝水面，远处渐隐进天色 | 第 5.1 节色板；远景雾退向地平线浅天色，「地图是一块漂在晴空里的桌面」 |
| 低视角跟随相机：角色在画面下部，能看到地平线 | 第 5.8 节：默认俯角 24°/30°，构图点在画面 60–64% 高度 |
| Q 版大头角色，待机浮动、走路摆动 | 第 5.6 节：头身 1:1，12 种族各有配件 |
| 地图上的悬浮兴趣点：立在细柱上、会转、地面有光圈 | 第 5.5 节：**自行设计**的五种外形扁平徽章 |
| 白色圆角界面、圆形图标按钮、底部正中的主入口 | 第 3–4、7 节：白色软糖面板、玩具按钮、公会徽章按钮 |

### 1.2 IP 红线（出现任何一条即判 P0 缺陷，所有角色自检）

- **不出现精灵球结构**：任何圆形元素（按钮、徽章、图标、3D 物体）都不能是「上下两色水平二分 + 中间横带 + 中心圆钮」，也不能是红白配色的球或圆。公会徽章按钮、艾琳娜入口、紧急「!」都按此自检。
- **不出现补给站结构**：方块 / 立方体立在细柱上是补给站的造型。我们的徽章**永远是扁平厚片（厚度 ≤ 宽度的 20%）**，五种外形里**没有方形**（第 5.5 节）；蓝色的物资运输是扇贝圆章，不是蓝方块。
- **不出现道馆**：不做塔形、多层平台上立着角色的地标；地标只用纽约真实建筑的卡通化版本。
- **不出现任何宝可梦形象**：包括剪影、配色组合（如黄色电气鼠的黄 + 红腮 + 黑耳尖的组合）、怪物球、蛋、孵化器。种族配件只用第 5.6 节列出的通用奇幻元素。
- **不出现宝可梦字体、字标或词汇**：不用 Pokémon Solid / Hollow 或仿制字体；文案不用「训练家」「道馆」「补给站」「精灵球」「孵蛋」等专有说法；不做红 / 蓝 / 黄三色阵营。
- 只借**通用视觉语言**（明亮地图、Q 版、悬浮兴趣点、白色圆角界面），所有图形自行设计。拿不准时去掉。

## 3. 界面 Token

全部 token 在 `index.html` 的 `:root`。Tailwind 同名映射：`--cute-teal-600` ↔ `bg-cute-teal-600`，`--quest-envoy-400` ↔ `bg-quest-envoy-400`。

> **迁移期硬规则**：新代码只用 `cute-*` / `quest-*` 命名空间与 `.cute-*` 原语。`slate / amber / red / sky / cyan / emerald / indigo / purple / violet / yellow` 在 `tailwind.config.js` 里被重映射成了大地色（写 `sky` 渲染出来是灰青），新代码用了它们就会把旧方向带回来。旧映射在发布阶段清理。

### 3.1 颜色

**三档用法（硬规则）**：每个强调色有 50 / 400 / 600 三档。
- **50 浅底**：标签、提示条、选中态的底色。
- **400 明亮色，只做图形**：3D 标记、图标底、进度填充、色条、卡片头部色块。它对白底不到 3:1，**不能承载文字，也不能单独作为白底上的图标颜色**。
- **600 深色，承载文字**：白字压在它上面 ≥ 4.5:1；它写在白底与自己的 50 上 ≥ 4.5:1；白底上的独立图标也用它。
- 黄色例外：暖黄底上永远放深棕字 `--cute-sun-ink`，不放白字。

### 3.3 字体

| 角色 | 栈（`--cute-font` / `--cute-font-display`） | Google Fonts | 字重 |
|---|---|---|---|
| 正文、按钮、数字 | `'Nunito', 'Noto Sans SC', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif` | Nunito、Noto Sans SC | Nunito 600/700/800/900 · Noto Sans SC 500/700/900 |
| 标题（≥ 20 px） | `'Nunito', 'ZCOOL KuaiLe', 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif` | ZCOOL KuaiLe（站酷快乐体） | 400（单字重） |

- **西文与数字落 Nunito**：圆头收笔，粗字重有软糖感，带等宽数字。会变的数字（金币、经验、距离、计时）一律 `.cute-num` 或 `tabular-nums`。
- **中文正文用 Noto Sans SC 的粗字重**：Google Fonts 上没有覆盖简体中文的圆体（M PLUS Rounded / Zen Maru 只覆盖日文汉字，简体字会缺字回退、字形混杂），所以用黑体的 700 / 900 换来同样敦实亲和的观感。Noto Sans SC 完整覆盖 GB 2312 / GB 18030 常用字。
- **标题用站酷快乐体**：简体中文字库（覆盖 GB 2312 常用字），负责可爱的个性；缺字时逐字回退到 Noto Sans SC，不会出方框。**只用于 ≥ 20 px 的标题**，正文用它会累眼。
- 链接已加在 `index.html`（`display=swap`；中文按 unicode-range 切片，只下载页面上出现的字）。沙箱里 Google 字体证书失败会回退系统字体，**截图里的字不是最终字体**。
- 新组件根节点加 `.cute-root`（或 Tailwind `font-cute`）。`index.html` 的全局规则把 `h1–h3` 设成了 Cinzel 衬线，`.cute-root` 内已抵消。`body` 的全局字体在发布阶段再切换。
- 禁止：衬线体、Cinzel、斜体强调、等宽字作标签、负字距、全大写字距拉宽的英文小标签（`SYSTEM_ELENA_CORE` 这类）。

4 的倍数：`--cute-sp-1…10` = 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40。屏幕边距：手机 16、桌面 24；面板内边距：手机 16、桌面 20；相邻触控目标间距 ≥ 8。

### 3.8 动效

| token | 值 | 用途 |
|---|---|---|
| `--cute-dur-tap` | 90 ms | 按下压扁 |
| `--cute-dur-fast` | 160 ms | 悬停、颜色 |
| `--cute-dur-base` | 240 ms | 状态切换、步骤点 |
| `--cute-dur-pop` | 380 ms | 弹出：模态、Toast、聚焦卡 |
| `--cute-dur-sheet` | 440 ms | 底部抽屉 |
| `--cute-ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | 进场、放大、选中（约 10% 过冲） |
| `--cute-ease-out` | `cubic-bezier(.22,1,.36,1)` | 抽屉、进度填充 |
| `--cute-ease-in` | `cubic-bezier(.55,0,.75,.2)` | 退场（先慢后快地缩回去） |

- 可爱感来自「按下去会扁、弹出来会过冲」，不是来自一直在动。**单次动画 ≤ 480 ms**；循环的待机动画（徽章浮动、「!」弹跳、公会徽章浮动）只用在主入口与紧急提示上。
- 关键帧（`index.css`）：`cute-pop-in`、`cute-pop-out`、`cute-sheet-up`、`cute-fade-in`、`cute-bounce`（挤压拉伸）、`cute-float`、`cute-wiggle`（拒绝的摇头）、`cute-pulse-ring`。Tailwind 简写：`animate-cute-pop / -sheet / -bounce / -float / -wiggle`。
- **减少动效**（`prefers-reduced-motion: reduce`）：去掉位移、缩放、弹跳与循环动画，只保留 ≤ 150 ms 淡入；按下仍有颜色与厚边变化。`.cute-*` 原语已内置；组件自写的动画必须同样处理（世界界面可复用 `components/world/ui/useReducedMotion.ts`）。3D 里对应：徽章停转停浮、光圈不脉冲、相机飞行改为直接切换（≤ 200 ms）。
- 震屏、闪白：本作不用。

### 3.9 图标

- 统一 **lucide-react**（已在依赖里），`strokeWidth` 2.25–2.5，圆端圆角（lucide 默认）。尺寸：按钮内 20，图标按钮 22，大图标按钮 26，卡片圆章 24，标签 16。
- 有含义的图标放进「圆章」：白底圆 + 600 色图标（卡片头、图钉），或 50 底圆 + 600 色图标（Toast）。
- 委托类型图标见 3.1 表；状态图标：已完成 `Check`、锁定 `Lock`、距离 `MapPin`、时间 `Clock`、金币 `Coins`、经验 `Sparkles`、信任 `ShieldCheck`、回到我 `LocateFixed`、视角 `Compass`、2D/3D `Layers`、公会 `Users`、艾琳娜 `MessageCircle`（入口用她的头像）。
- **紧急救援不用 `LifeBuoy`**（红白相间的救生圈过于接近红白圆形的禁区），用 `HeartPulse`。
- 公会徽章（契约终端主入口）用自绘 SVG：白色圆角盾 + 暖黄四角星（附录 B）。不用 emoji 作图标（上一版的 🛡️📷🏃 迁移时替换成 lucide 或去掉）。

### 5.2 材质与着色

- **共享一张卡通渐变**：`MeshToonMaterial` + 4 阶 `gradientMap`（`DataTexture`，亮度 `0.60 / 0.78 / 0.92 / 1.0`，`NearestFilter`），建筑、树、地标、玩家共用。背光面落在 60–78%，再被半球光染成偏蓝的「有色阴影」——阴影是浅蓝灰，不是灰黑。
- 地面、道路、水：`MeshLambertMaterial`（顶点色）或在现有地面着色器里换色；水面用两档卡通波纹（亮带随时间缓慢移动）+ 岸线白色浪花，不要高光反射。
- 材质角色（沿用 `materials.ts` 的按角色共享原则）：`ground` · `water` · `shore` · `building`（实例色 = 墙色，屋顶帽 / 压顶由顶点属性区分，同一个 draw call）· `foliage` · `structure`（地标，顶点色）· `marker`（不受光的自发光式 ShaderMaterial）· `player` · `path` · `cloud` · `mote`。
- **建筑着色器整体瘦身**：去掉上一版的密集窗格、屋面设备箱、檐口阴影线、楼层灯带。保留且只保留：墙脚 AO（更浅，60%→85%）、屋顶帽与白色压顶、稀疏圆角窗（每面每层 ≤ 2 个，远处淡出）、夜间窗灯。
- 玩家与徽章加**边缘光**（fresnel，白色，强度 0.25–0.35，`shader-cookbook.md` 配方 a），让它们从地图上「浮」出来。
- **不要粗黑描边**（CLAUDE.md）。需要分离时用：白色压顶 / 白边、浅色边缘光、同色系深一档的底边。
- **色调映射**：`NeutralToneMapping`，曝光 1.0。`grade.ts` 的「冷影暖光 + S 曲线」是大地色方向的调色，换成只做「中饱和像素 +6% 饱和、高饱和与粉彩不动」的轻调色，或直接退回 Neutral。不加后处理 pass（与上一版一致，手机 0 pass）。
- 纹理：图标图集 1 张（512²，`CanvasTexture`，5 个类型图标 + 勾 + 锁 + 「!」），渐变图 1 张（4×1），总纹理 ≤ 6。

### 5.3 光照与阴影

| 光源 | 白天 | 夜晚 | 投影 |
|---|---|---|---|
| 主光（太阳 / 月亮，同一盏） | `#FFF6E2`，2.6，正午仰角约 55°（比真实高，阴影短） | `#A9BCFF`，0.9，仰角 52° | 高档投影，低档不投影 |
| 半球光 | 天 `#DDF1FF` / 地 `#C4E8A6`，1.4 | 天 `#34477F` / 地 `#141D38`，0.8 | — |
| 补光 | 去掉（卡通渐变的下限已经保证背光面亮度） | — | — |
| 委托标记、窗灯、街灯 | 自发光，不用动态点光源 | 自发光加强 | — |

- **短阴影**：上一版白天的长投影把半条街压黑。太阳仰角下限抬到 35°（日出日落时段也一样），阴影长度 ≤ 楼高的 0.7 倍。
- **高档**（桌面）：一盏方向光阴影，2048，`PCFSoftShadowMap`，投影物 = 建筑 + 地标 + 玩家 + 徽章；树用贴地软影片。阴影强度通过半球光保证暗部 ≥ 65% 亮度，阴影偏蓝。
- **低档**（手机 / ≤ 4 核）：**关闭实时阴影**（`renderer.shadowMapSize` 报 0），全部用贴地软影：玩家、徽章、树各一块径向渐变圆片（同一个 InstancedMesh，1 个 draw call），建筑脚下一圈 AO 烘进地面顶点色。可爱风格里软影片比实时阴影更「对」，还省掉整个阴影 pass。

### 5.4 造型语言

- **建筑**：低矮、圆润、粉彩的简化体块。
  - 竖向棱倒角：半径 = clamp(0.12 × 短边, 1.2 m, 4 m)。用 3 种按长宽比预制的倒角盒几何（方 / 长 / 高）实例化，非均匀缩放造成的倒角变形控制在 1.5× 内；或在着色器里按到棱的距离弯曲法线做「视觉倒角」，效果相近、零三角形。
  - 屋顶：内缩 0.4 m 的「枕形」屋顶帽（0.6–1.5 m 厚，顶面圆鼓）+ 一圈白色压顶。
  - 高度压缩：真实高度 h ≤ 40 m 时 `8 + 0.45h`，> 40 m 时 `26 + 14·ln(h/40)`，上限 72 m；帝国大厦等地标单独做到 ≤ 95 m。中城自然比别处高，但不再是峡谷。
  - 密度：每个街区高档 ≤ 3 栋、低档 ≤ 2 栋，楼与楼之间留 ≥ 4 m 缝、离街道退 3 m（露出奶白人行道）。总楼数降到上一版的 35–50%。
  - 每栋楼随机取 5 色之一，相邻同色 ≤ 2 栋。
- **树**：棒棒糖圆树。树冠 = 低面数圆球（icosahedron 细分 1，约 80 三角）半径 5–8 m（夸张），树干 = 6 边圆柱，高 4–6 m，半径 1.2 m；3 种绿随机；树冠轻微风摆。公园里成簇，几条大道两侧稀疏成排。
- **水**：平面 + 岸线浪花 + 浅水带；不做波浪几何。
- **地标**（同一卡通语言）：帝国大厦 = 奶油色多级圆角退台 + 暖黄尖顶；时代广场 = 奶白广场 + 4 块粉彩发光色块；布鲁克林大桥 = 沙色双塔（圆拱）+ 白色拉索 + 奶黄桥面；中央公园 = 鲜绿草地 + 水库 + 密集棒棒糖树 + 奶黄小径。
- **比例关系**：默认视距下玩家（约 40–50 m 世界高度，见 5.6）高过普通楼（8–26 m），矮于中城塔楼——「玩具城里的大头小人」。

### 5.6 玩家：Q 版大头小人

- **比例**：总高 2 个头单位——头直径 1.0（略扁，纵向 0.94）、躯干 0.62、腿 0.38；手臂短圆柱，手是圆球；脚是小椭球。
- **屏幕尺寸**：默认视距下手机 72 px、桌面 64 px 高；世界高度按视距换算并夹在 10–60 m（默认视距下约 40–50 m）。缩到总览时最小 28 px。
- **表情**：竖椭圆大黑眼（宽 0.11、高 0.15，间距 0.36，略低于头中线）+ 白色高光点；腮红 `#FF9AA2` 60%；小嘴微笑。眼睛做成压扁的深色小球（不用纹理），每 3–5 s 随机眨眼（纵向缩到 0.1，120 ms）。

### 5.8 相机（GO 式低视角）

| 参数 | 上一版 | 本版 |
|---|---|---|
| 俯角范围 `camera.tilt`（视线相对地平面） | 35°–70° | **20°–70°**（`TILT_MIN` 下调；QA 的 M2-07 断言需同步） |
| 默认俯角 | 52° | **手机 30°、桌面 24°**（顶部露出地平线与天空） |
| 默认视距 `camera.zoom`（到焦点的米数） | 1300 | **手机 420、桌面 480**；若最近 3 个委托进不了构图安全区则自动拉远，夹在 380–1400 |

### 5.9 氛围

- **卡通云**：12–20 朵，每朵 3–5 个合并的低面数球（一个 InstancedMesh），环绕在远景雾带附近、高度 120–260 m，缓慢漂移；受光面白、背光面 `#DCEBF7`；夜里 `#2E3F73` 60% 不透明。不受雾影响。1 个 draw call。
- **飘浮光点**：桌面 60、手机 30 颗，玩家周围 150 m 内缓慢上升并淡出；白天 `#FFF6C8`（像花粉），夜里 `#FFE38A`（像萤火虫）。一个 `Points`，圆点在着色器里画，不用纹理。减少动效时关闭。
- 不加：雨雪天气、镜头光斑、景深、色差、暗角。

### 5.10 渲染预算账本

美术总监质量线：**每个测量视角（V1–V4）的 draw call ≤ 改版前同视角读数的 1.2 倍**（V1 改版前 28 → 本版 ≤ 34）；本轮硬上限 60，超过 34 必须写明理由与对应的画面收益。三角形、纹理按 brief 7.1（桌面 ≤ 500k / 手机 ≤ 250k；纹理 ≤ 32 / ≤ 16）。3D 分包 ≤ 720 KB / 200 KB gzip。

建议账本（高档 V1，颜色 pass）：天空 1 · 地面（陆地 / 城区 / 公园 / 道路合并）≤ 2 · 水与岸线 2 · 建筑（墙 + 屋顶帽 + 压顶同一实例化几何）1 · 树（干 + 冠合并）1 · 地标合并 ≤ 4 · 委托标记 ≤ 5 · 玩家 ≤ 3 · 路径 1 · 云 1 · 光点 1 · 贴地软影 1 · 特效池 ≤ 2 ≈ **24**；高档阴影 pass（建筑、地标、玩家、徽章）约 +7 ≈ **31**。低档无阴影 pass ≈ 24。
省出来的空间来自：去掉密集窗格与屋顶设备（着色器更便宜）、楼数降到 35–50%、地标与树合并、低档关阴影。

## 6. 2D 回退地图（Leaflet · `MapBoard.tsx`）

- **瓦片**：换成 Carto Voyager 栅格（同一个 `basemaps.cartocdn.com` 主机，不新增域名、不新增数据采集）：`rastertiles/voyager_nolabels` + `rastertiles/voyager_only_labels`（标签层 70% 不透明）。

## 9. 迁移规则与验收

### 9.1 迁移规则

1. **只加不删**：旧 token（`--gold`、`--parchment`、`--stone-*` 等）、旧类（`.rune-panel`、`.glass-panel`、`.parchment-noise`、`.vignette`）、旧 Tailwind 重映射在迁移期全部保留，发布阶段统一清理。新组件不再使用它们。
2. 新组件根节点加 `.cute-root`；颜色只用 `cute-*` / `quest-*`；类型色调用 `.cute-tone-<transport|hunt|build|envoy|rescue>`。
3. 类名尽量写完整字面量。Tailwind 按用量裁剪：`.cute-tone-*` 与 `.cute-pin-*` 两族已整族保留，可以拼接；其余原语（`.cute-card` 等）必须以完整类名出现在 `components/**` 或 `App.tsx` 里才会进 CSS。类型 → 色调映射建议写成对象字面量：`{ 物资运输: 'transport', 魔物讨伐: 'hunt', 迷宫建设: 'build', 异界交涉: 'envoy', 紧急救援: 'rescue' }`。
4. 接口契约一律不变：`WorldMap` 的 props 与 `onFallback`；`worldEvents`（recenter / resetView / pulse / celebrate）；`?debug=1` 下的 `render_game_to_text` 与 `__world`（tapBeacon、focusQuest、setHour、recenter、stats）；`lib/progression.ts` 结算函数；世界界面组件的 props；全部 `data-testid` 与 aria-label。可以加字段，不改名、不删除。
5. 所有接取都走 `App.tsx` 的 `handleAccept`；觉醒每一步的主按钮在所有视口完整可见可点（`qa-r2-awaken-sizes.mjs` 33/33）。
6. 新 token 需求写进 `docs/studio/handoff/cute-<分工>.md`，不要在组件里写裸 hex 自造颜色（3D 色板在场景代码里落成常量是允许的，取值以 5.1 为准）。
